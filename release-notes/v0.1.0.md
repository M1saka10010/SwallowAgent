# SwallowAgent v0.1.0

## Breaking change: Token → device public-key authentication

Deploy the matching [SwallowMonitor commit 955dde6](https://github.com/M1saka10010/SwallowMonitor/commit/955dde6f6275a51e6ed2080027b8bf3d17d81930) or a compatible later version **before migrating Agents**. Back up the Monitor database consistently and keep the original host records. Old Token Agents will temporarily be offline after the Monitor upgrade.

- Ed25519 challenge authentication over verified WSS; one-time enrollment credentials replace manual public-key copying.
- Fixed-version bootstrap downloads and SHA-256 verification for Linux amd64/arm64.
- Dedicated migration from the standard v0.0.2 Linux/systemd installation; preserve host identity, history and collection settings. Generate the enrollment credential on the original host, not a new record.
- Automatic executable temporary-directory selection handles `/tmp` mounted `noexec`.
- `swallow-agent -version` and `system_info.agentVersion` report `v0.1.0`.
- Windows amd64 supports manual registration and reporting; file ACL policy is managed by the operating system/user, not the Agent. Linux installation/migration scripts do not install a Windows service.

In the updated Monitor, select **v0.1.0** as the target Agent release and copy the appropriate new-install or Token-migration command. Do not use the migration script for ordinary upgrades of an already public-key-configured Agent.

## Verification and limitations

Linux/Windows native tests gate release. RC migration was tested with real systemd in an isolated Docker container: original identity/history retained, reporting resumes after service restart, repeated migration leaves files unchanged. The noexec fix was tested on an actual noexec mount. Online download/checksum/idempotent execution was tested separately; the first actual RC migration used checksum-verified local release assets.

Local rollback cannot undo a completed server-side key binding: retain the generated private key for retry. Report writes have no persistence acknowledgement. Checksums from the same release are integrity checks, not independent publisher signatures.
