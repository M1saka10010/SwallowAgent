# v0.1.1

- Adds a dedicated standard Linux systemd upgrade entry point: bootstrap.sh --version v0.1.1 --mode upgrade. No enrollment token is needed; configuration, device key and service identity are preserved.
- Adds optional HTTPS GitHub proxy prefixes for bootstrap asset downloads. Only use a trusted proxy; same-source checksums are not independent signatures.
- Verifies candidate checksums and version, rejects downgrades and unknown layouts, keeps a recovery binary, and attempts rollback on failure. Rollback confirms service stop state and resets the target service start limit before restarting the original binary.
- Fixes signal forwarding during child process launch.

Deploy companion Monitor commit 83899de (or later) to get automatic release selection, reported-version comparison and upgrade commands. Monitor is not deployed automatically.

The Token migration entry remains separate and is only for v0.0.2 standard installations. Do not rerun migration after a regular upgrade: its original binary checksum marker is intentionally unchanged. Windows and custom service layouts require manual upgrades.

Validation: frontend 120 tests/build; both repositories Go tests/vet; isolated upgrade/rollback mocks and 18 deterministic bootstrap signal-window cases. Real systemd stop-timeout and StartLimit rollback acceptance has NOT been completed due to test-fixture write permissions. An active service is not proof of authentication or report delivery; verify version and fresh samples in Monitor after upgrading. Back up configuration and private key first.
